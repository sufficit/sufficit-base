# Datas do ciclo atual legado no Blazor

Problema: RecurringItem enviava o início agregado de Contract e a API rejeitava a troca pelo início do último serviço renovado (`Aggregate contract start cannot replace the latest service start`).

Solução: Contract.LegacyPeriodEdit é um pedido tipado, transitório e NotMapped, com ServiceId e instantes UTC. O writer MySQL exige snapshot original/revisão, identidade atual, período válido e agregados intactos. Consome o pedido antes de persistir, preserva o início agregado e predecessores, atualiza o snapshot exato e usa o histórico/outbox existentes. A guarda de edição agregada permanece ativa para clientes antigos.

Blazor: campos de legado representam início/fim do ciclo atual em Brasília, preservando os horários e segundos. Save envia o pedido explícito mesmo sem mudança de datas para preservar a precisão. A resposta deve confirmar as datas antes do snackbar de sucesso. IA usa os mesmos callbacks, nomes e alcance do formulário. Native mantém campos de vigência. Reference lock: editor existente, DESIGN.md e componentes SUI; apenas rótulos e indicação do alcance foram adicionados.

Validação: regressão falhou antes (start esperado 2032-01-30T00:12Z, observado 2032-02-01T00:00Z), passou depois. 28 testes EFData (edição atual, predecessores reconstruídos intactos, revisão obsoleta, identidade/fuso/período/agregado inválidos e comandos históricos); 17 testes Blazor (datas Brasília, preservação de horários, agregados intactos e resposta antiga da API recusada). Builds de publicação oficiais passaram, com warnings preexistentes. Sem alteração de dados reais para testar; formulário autenticado não foi exercitado em produção.
